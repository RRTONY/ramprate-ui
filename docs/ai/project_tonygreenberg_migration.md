# Tonygreenberg Migration

> TonyGreenberg.com Manus-to-Netlify migration plan, now v2 (2026-08-22) adding AI chatbot + Supabase-backed publish-approval workflow — stack decisions, PDF deliverables, phase plan, live SEO diagnostics

**Context:** Tony's assistant/AI ("Tony's AI") pitched a heavy 10-vendor stack (Builder.io, Vercel, Cloudinary, Algolia, Supabase, Plausible, etc.) to get TonyGreenberg.com off Manus after a week of Manus failures (broken formatting, broken images, billing failures despite credits, poor QA, lost context, high token costs). Chitraket countered with a lighter recommendation reusing infrastructure already proven on [project_ramprate](project_ramprate.md) rather than adopting five new tools at once.

**Recommended stack (Chitraket's counter-proposal, accepted as the plan basis):**
- GitHub + Netlify (not Vercel) — identical pipeline already running RampRate UI, no new bill/learning curve.
- Sanity (not Builder.io Publish) — same CMS non-technical staff already have a written guide for (see [reference_sanity_cms_guide](reference_sanity_cms_guide.md)).
- Cursor + Claude Code connected directly to the repo — the actual fix for Manus's core failure mode (AI editing a closed proprietary workspace vs. real files with real git history).
- Deliberately skipped for now: Cloudinary, Algolia, Supabase, Plausible — no current need, can layer in later.

**Deliverable produced 2026-07-23:** `TonyGreenberg-Manus-to-Netlify-Migration-Plan.pdf` (repo root, untracked) — a 4-page branded PDF for Tony to read before work starts, built via the same pattern as [reference_sanity_cms_guide](reference_sanity_cms_guide.md) / [project_supplier_intake](project_supplier_intake.md)'s manual guide: HTML source styled with site brand tokens (`#0a0f1a` dark cover, `#d4a843` gold, `#f5f0e8` warm, Georgia-style display headings) written to session scratchpad, printed via `headless Chrome --print-to-pdf`, two-tier `@page` rule (`@page :first { margin: 0 }` for the full-bleed dark cover, `@page { margin: 20mm 18mm }` for content pages) — same technique documented in [project_supplier_intake](project_supplier_intake.md). User explicitly chose "Branded PDF" over a plain markdown handoff doc when asked, since this is a business-decision document for Tony (not an implementation spec for whoever operates Manus) — different from the `scripts/tonygreenberg-*-handoff.md` pattern used for technical handoffs.

**Plan content (6 phases):** (1) Export & Inventory from Manus, no live changes; (2) Stand up GitHub/Next.js/Sanity/Netlify foundation + staging URL; (3) Rebuild content in Sanity + Next.js templates; (4) QA gate (visual diff, link check, spelling, perf/a11y, 301 redirect mapping) — nothing ships until this passes in full; (5) Cutover (DNS to Netlify, Manus kept live untouched during an overlap window, cancel Manus after the new site proves stable); (6) Handoff — Sanity Studio walkthrough for Tony, ongoing code-change workflow (request → Cursor/Claude Code → preview deploy → review → merge → live).

Same "no code access to tonygreenberg.com, separate Manus-operated codebase" constraint noted in [project_supplier_intake](project_supplier_intake.md) and [project_biochain_sourcing](project_biochain_sourcing.md) applies — once Tony approves, execution will likely still be handoff-doc-driven unless direct repo access is granted.

**Live diagnostic findings (2026-08-22, curl against tonygreenberg.com, not memory-recalled):** on-page SEO is actually solid already — unique title/meta/OG/Twitter/canonical/JSON-LD per page (verified homepage vs `/about`), `sitemap.xml` (78KB) and `llms.txt` both live, `robots.txt` correctly allows Google/Bing/AI crawlers while blocking Ahrefs/Semrush/Amazon scrapers. The real problems are hosting-layer: every response sends `cache-control: no-cache, no-store, must-revalidate` (no CDN caching, direct CWV/TTFB tax), and headers expose `x-manus-proxy-mode: transparent` + `x-powered-by: Express` confirming the site is still fully proxied through Manus, not infrastructure RampRate controls — consistent with the prior Manus failure history (broken formatting/images, billing lockouts). Bots (Googlebot/GPTBot UA) get a leaner ~9KB HTML response vs ~375KB for a plain browser UA, but content-parity check confirmed this is legitimate dynamic rendering (full real text present, not cloaking).

**PDF pagination gotcha (fixed same session):** the cover div was hardcoded to `height:297mm` (A4) while Chrome's `--print-to-pdf` defaults to Letter (279.4mm tall) when no page size is set in CSS — this silently overflowed the cover onto a second page and orphaned a phase-card. Fix: add explicit `size: A4;` inside both the `@page` and `@page :first` rules, plus `page-break-inside: avoid` on every boxed component (`.finding`, `.phase-card`, `.stack-box`, `.callout`, tables/rows). Worth checking for on any future branded PDF built with this pattern — `wc -l`/visual page-count alone won't catch it, has to be read back page-by-page.
