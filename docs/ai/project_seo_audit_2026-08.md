# Seo Audit 2026 08

> Live SEO audit of ramprate.com (2026-08-04) - what was actually broken vs. working, and fixes applied

Chitraket reported "SEO isn't working," specifically claiming robots.txt/sitemap.xml were broken, llms.txt was missing, and the site ranks ~#20 in search when it should be #1. Tested https://ramprate.com/ live (curl + WebSearch) rather than trusting the claim.

**What was actually fine:** `/robots.txt`, `/sitemap.xml`, and `/llms.txt` all return HTTP 200 with correct content in production (`src/app/robots.ts`, `src/app/sitemap.ts`, `public/llms.txt`). Every registered route has a proper `<title>`, meta description, canonical tag, and OG tags via the `generateMetadata()` + Sanity `pageSeo` system described in [project_seo_metadata](project_seo_metadata.md). So the premise "sitemap/robots not working" did not reproduce - always verify infra complaints against the live site before acting on them.

**What was actually broken (found via `site:ramprate.com` WebSearch cross-referenced with curl):** Google has several pre-migration WordPress URLs indexed that 404 in production because `public/_redirects` had no rule for them - Next.js's own default trailing-slash-stripping 308 fires instead, landing on a path with no matching page. Confirmed and fixed in `public/_redirects`:
- `/ramprate-impact/` (indexed, titled "Impact - RampRate") → now redirects to `/impactsoul`
- `/faq/` (indexed, titled "Frequently Asked Questions") → now redirects to `/about` (best-guess target, no direct new-site FAQ equivalent exists - flagged to Chitraket as needing confirmation)
- `/category/iaas/`, `/category/web3/` → now redirect to their `/blog/category/*` equivalents (both already return 200)
- `/blog/page/*` (WordPress pagination) → now redirects to `/blog`

**How to apply:** if the user reports more "SEO not working" complaints, check `site:ramprate.com` results for other legacy indexed URLs not covered by `public/_redirects` - this migration (WordPress → Next.js/Sanity) left several URLs indexed that were never mapped. The pattern to search for: any URL 308-redirecting to its own non-trailing-slash form that then 404s means no `_redirects` rule exists for it.

**Also fixed:** the `Organization` JSON-LD telephone field (`src/components/shared/JsonLd.tsx`, `organizationJsonLd()`) was emitting corrupted bidi-control unicode characters (e.g. U+202A/202C) around the phone number, sourced from `siteSettings.phone` in Sanity - likely pasted in with hidden formatting marks. Added a sanitizing `.replace()` in `organizationJsonLd()` so this is robust regardless of what ends up in the Sanity field.

**The unresolved, honest part - ranking position:** WebSearch for peptide-sourcing-related queries showed RampRate BioChain does not appear on page 1; dedicated peptide-industry sites (RAMpeptides, pspeptides.com, coolcryo.com, biofusionaminos.com, protidehealth.com) outrank it. This is a content depth / backlink / domain authority gap, not a technical defect - no code fix moves a site from position 20 to position 1. That takes sustained content publishing, external backlinks, and time (typically months). Framed this honestly to Chitraket rather than implying a code change would fix ranking position directly.

**Follow-up same day - the real root cause:** Chitraket pushed back that sitemap/robots/llms.txt "aren't working" and wanted every page added. Re-verified: infra was fine, but re-auditing surfaced the actual site-wide bug. Root layout (`src/app/layout.tsx`) sets a default `alternates.canonical: "/"`. Next.js metadata inheritance means any page that doesn't explicitly override `alternates.canonical` in its own `metadata`/`generateMetadata()` silently inherits that root default - so the page's canonical tag points at the homepage instead of itself. Live-verified via curl that **10+ major pages** were doing exactly this: `/about`, `/web3`, `/growth`, `/proof`, `/contact`, `/impactsoul`, `/private-advisory`, `/values`, `/thinking`, `/service-provider-intelligence-index`, plus all 3 `/payments-advisory*` pages - all telling Google "the canonical version of this page is the homepage," which suppresses independent ranking for every one of those pages. This is almost certainly the dominant cause of poor organic rankings sitewide, far more impactful than the earlier redirect/llms.txt gaps. Fixed by adding `alternates: { canonical: "/<route>" }` to each page's metadata object (confirmed `withSeoOverrides()` in `src/lib/sanity/seo.ts` spreads `...fallback` first, so Sanity-driven pages using `FALLBACK_METADATA` don't lose this).

**How to apply:** any NEW page added to this codebase MUST set its own `alternates: { canonical: "/its-route" }` in its metadata export - the root layout's default does not provide this per-page, contrary to what you'd expect from Next.js metadata merging. Add this to the checklist for every new practice/content page. Also added the previously-missing pages to `sitemap.ts`'s static routes (`/biochain/catalogue`, `/biochain/process`, `/sourcing/process`, `/payments-advisory` + its 2 subpages) and expanded `public/llms.txt` to list BioChain and Payments Advisory sections plus the remaining orphaned pages (howwework, values, SPY index, privacy, terms) that were previously absent.

**Second follow-up, same day - Chitraket was right that sitemap.xml itself was broken:** pasted a browser XML parse error ("EntityRef: expecting ';'" at line 235). Root cause confirmed two distinct bugs in `src/app/sitemap.ts`:
1. Every blog post's `<image:loc>` URL came straight from Sanity's CDN (`urlFor(...).url()`), which always contains a raw `&` in its query string (`?w=1200&auto=format`). XML text requires `&amp;`, not a bare `&` - Next's built-in sitemap serializer does not escape this field, so the feed became invalid XML partway through (browsers/Search Console stop parsing at the first malformed entity, silently dropping everything after it). Fixed with a small `escapeXml()` helper applied to the image URL.
2. `sitemap.ts` also had a `pageRoutes` section that mapped **every** Sanity `page`-type document's slug to a URL, with no check against real Next.js routes. Since there's no generic `/[slug]/page.tsx` catch-all (every route is its own explicit `page.tsx`), this produced duplicate entries for routes already in `staticRoutes` (about, impactsoul, expertise, etc., each listed twice with different priorities) and, worse, live URLs for leftover WordPress-migration Sanity docs that have no matching route at all (`/purpose-promise`, `/our-process`, `/impact-scope` - confirmed 404 live). Deleted this section entirely; removed the now-unused `allPageSlugsQuery` from `src/lib/sanity/queries.ts`.

**How to apply:** verified the fix by running `next dev` locally, curling `/sitemap.xml`, and parsing it with `xml.dom.minidom` - confirmed valid XML, zero phantom/duplicate URLs, zero unescaped `&`. If any future field pulls a raw external URL (Sanity CDN, third-party embeds) into `sitemap.ts`, it must go through `escapeXml()` first. Do not reintroduce a Sanity `page`-slug-to-URL mapping in the sitemap unless a real catch-all route is built to serve those slugs - until then, every real route lives explicitly in `staticRoutes`.

See [project_seo_metadata](project_seo_metadata.md) for the Sanity-driven metadata system, [project_biochain_sourcing](project_biochain_sourcing.md) for BioChain route history.

**Full site-wide pass (2026-08-18):** GSC flagged `/blockchain/` and `/flow/peer-assessment` as Soft 404. `/blockchain/` was a stale report - the `_redirects` 301 already works live, just needs "Validate Fix" clicked in GSC. `/flow/peer-assessment` was real: a tokenless duplicate of `/flow/peer-review/[token]`, listed in `sitemap.ts` and NOT in `robots.ts` disallow, so it always rendered "Invalid Review Link" to crawlers. User then asked for a full site audit ("check all pages... better seo"), which surfaced more:
- **My own earlier "fix" that session was broken**: I'd added `/flow/peer-assessment/` (trailing slash) to `robots.ts` disallow. Next has no `trailingSlash` config, so the route serves without one - a disallow entry with a trailing slash only prefix-matches paths that have one, so it silently never blocked anything. Fixed to `/flow/peer-assessment` (no slash) + added `robots: {index:false, follow:false}` directly on the page as defense-in-depth. **How to apply:** when adding a `robots.ts` disallow entry, check whether the target route is a static leaf (no trailing slash in `next.config.ts` → no trailing slash on the real URL) vs. a route with dynamic children (trailing slash is correct there, since it needs to prefix-match `/parent/[child]`).
- `/flow/admin` (internal admin dashboard) was in `sitemap.ts` and NOT disallowed - removed from sitemap, added to `robots.ts` disallow + page-level noindex.
- Added `/supplier-intake-long` to `robots.ts` disallow (page already had its own noindex meta, but robots.txt didn't block crawling).
- `src/components/shared/JsonLd.tsx`: `JSON.stringify(data)` fed straight into `dangerouslySetInnerHTML` with no `<` escaping - a CMS string containing `</script>` would break the tag. Added `.replace(/</g, '\\u003c')`.
- `organizationJsonLd()` had two real bugs: never received a `logo` (layout.tsx just didn't pass one, despite Sanity having the field) - fixed by resolving it via `urlFor()` in `layout.tsx`. And it destructured `address` as `{street,city,state,zip}` but Sanity's `address` field is `type:'text'` (a plain string) - always produced a broken `PostalAddress` with only `addressCountry` populated. Fixed by treating `address` as a plain string in both the type and the JSON-LD output, rather than changing the Sanity schema (schema change would need a content-model decision, flagged as optional follow-up, not made unilaterally).
- 9 marketing pages (`growth`, `web3`, `impactsoul`, `private-advisory`, `about`, `proof`, `thinking`, `contact`, `expertise`, `values`) had **no** `openGraph`/`twitter` in their fallback metadata at all. Not a live bug today (they inherit the root layout's OG default), but a latent one: Next doesn't deep-merge nested `openGraph` objects between layout and page, and `withSeoOverrides()` (`src/lib/sanity/seo.ts`) unconditionally rebuilds `openGraph:{...fallback.openGraph,...}` the moment ANY Sanity `pageSeo` doc exists for that route - since `fallback.openGraph` was undefined, the OG image would silently vanish the instant an editor created a CMS SEO record for one of these routes, with zero visible error. Fixed by giving every page a complete, self-contained `openGraph`+`twitter` block (pattern already correct in `src/app/howwework/page.tsx` - used as the reference). Also added missing `images` to `sourcing`, `process`, `careers`, `blog` (had partial OG), and `twitter` cards to `blog/[slug]`/`thinking/[slug]` (had OG via real Sanity images, just no twitter sibling).
- Root layout loaded Playfair Display/DM Sans/JetBrains Mono via a render-blocking `@import url(fonts.googleapis.com...)` in `globals.css` instead of `next/font` - direct CWV/LCP hit on every page, in violation of [project_ramprate](project_ramprate.md)'s own stated font rule. Converted to `next/font/google` in `src/app/layout.tsx` (self-hosted `.woff2`, applied as `variable` classes on `<html>`), removed the `@import` and the now-redundant `:root` font fallback declarations from `globals.css` - Tailwind's `@theme inline` block still resolves `--font-display`/`--font-body`/`--font-mono` fine since next/font defines the same variable names on `<html>`.
- Accessibility (mobile-first indexing = ranking signal, not just UX): added missing `aria-label`s to every icon-only button found (`TestimonialsCarousel` prev/next/dots, `SiteSearch` close/send/new-chat), linked every orphaned `<label>` via matching `id`+`htmlFor` across the main lead-gen forms (`ContactForm`, `PaymentsIntakeForm`, `ClientIntakeForm`, supplier `formShared`, `attorney-rfi`), and added `aria-hidden="true"`+`tabIndex={-1}` to the two click-to-dismiss modal backdrops (`HeaderSearch`, `SiteSearch` - both already had Escape-key handling elsewhere, just weren't marked non-interactive).
- `llms.txt` restructured to add a proper `## Optional` section (privacy/terms/sitemap) per the llmstxt.org spec - previously flat, no signal for what an LLM agent should skip under context pressure.
- **Reconfirmed, did NOT touch**: `/biochain-sourcing` duplicate-content-vs-`/biochain` situation - this is a deliberate, previously-litigated decision (see [project_biochain_sourcing](project_biochain_sourcing.md) line ~68), not a new bug. Left its sitemap/robots/canonical exactly as-is.
- **Flagged for user decision, not auto-changed** (copy/business-tone calls, not technical bugs): `private-advisory` title (82 rendered chars) and description (281 chars, ~1.75x the 160 guideline) are the most over; `growth` title and `sourcing`/`web3`/`blog`/`howwework` descriptions are mildly over (162-174 chars); `about`/`contact`/`expertise` fallback titles are single generic words ("About", "Contact", "Expertise") with no keyword value. Drafted tighter alternatives but did not apply - word choice is the user's call, not mine.

**How to apply going forward:** this codebase's `withSeoOverrides()` CMS-merge pattern means ANY page-level fallback missing a full `openGraph`/`twitter` block is a latent bug waiting for someone to create a matching Sanity `pageSeo` doc - when adding a new page, always give it a complete self-contained OG/Twitter block up front (copy the `howwework/page.tsx` pattern), don't rely on inheriting the layout default even if it currently "works."
