> Supplier intake: two-stage form (2026-07-10) + inline scoring/approval workflow in the shared Apps Script (2026-07-14), Google Sheet/Drive backend

**Two-stage rebuild (2026-07-10):** what was a single 64-field form is now split:
- **Stage 1** — `/supplier-intake`, `src/components/supplier/SupplierIntakeStage1Form.tsx`, 18 fields, no uploads, ~2-3 min, public. Submits to `src/app/api/supplier-intake/route.ts`.
- **Stage 2** — `/supplier-intake-long/[token]`, `src/components/supplier/SupplierIntakeStage2Form.tsx`, ~41 fields incl. document uploads, 6 steps. Link-gated by a per-supplier token generated on Stage 1 submit. Submits/autosaves to `src/app/api/supplier-intake-long/route.ts` (also has a GET for resume-prefill).
- Shared rendering/validation lives in `src/components/supplier/formShared.tsx` (`FieldRenderer`, `Card`, `StepBar`, Yup schema builder) — driven entirely by the field schema in `src/lib/supplier-intake-fields.ts` (`STAGE1_STEPS`/`STAGE2_STEPS`), so the UI can't drift from the field list.
- `/supplier-intake-long/[token]` is deliberately **not** in `src/lib/site-pages.ts` — it's link-gated/private, same exclusion rule as `/attorney`-style pages. See [project_site_search](project_site_search.md).

**Token mechanics:** Stage 1 submit generates a UUID token in the Apps Script (`Utilities.getUuid()`), writes it plus a pre-built `Stage 2 Link` (`<stage2UrlBase> + token`) and `Stage 2 Status: Pending` into the Sheet row. `src/app/api/supplier-intake/route.ts` sends its own `stage2UrlBase: 'https://ramprate.com/supplier-intake-long/'` in every Stage 1 payload; the script only falls back to `DEFAULT_STAGE2_URL_BASE` if a caller omits it — keeps the script safely shareable across sites. Once Stage 2 is submitted (`final: true`), status flips to `Complete` and the token is rejected on any further read/write (single-use link).

**Stage 2 approval workflow + inline scoring (added 2026-07-14, per a "Stage 2 Form — Full Plan" PDF the user shared):**
- **`Stage` column** (`Stage 1 Submitted` → `Approved for Stage 2` / `Rejected` → `Stage 2 Complete`) — separate from `Stage 2 Status` (which still tracks the Stage 2 *form's* own autosave/complete progress). Rob/whoever screens intake flips this dropdown manually in the Sheet.
- **`Supplier ID`** (`SUP-2026-0001`, sequential, scoped per Sheet tab/site — not global — since the Supplier Token, not the Supplier ID, is what actually links Stage 1/Stage 2 data) and **`Source Site`** (`ramprate`/`tonygreenberg`, derived from `projectName`/hostname) added at Stage 1 submit.
- **Auto-email on approval**: an installable `onStageEdit` trigger (in `supplier-intake-apps-script.gs`) fires when `Stage` is set to `Approved for Stage 2`, emailing the supplier their Stage 2 link via `MailApp`. Must be an *installable* trigger, not the automatic simple `onEdit(e)` — simple triggers can't call `MailApp`, and installable `onEdit` triggers only fire on real human edits in the Sheets UI, never on programmatic/API writes (so testing this via curl/script is impossible — confirmed by observation, not just docs). This doesn't replace staff manually sending the link (still possible/optional) — it's additive.
- **Self-installing, not manual** (added same day after user pushback): originally required running `installStageApprovalTrigger()` once by hand from the Apps Script editor. User explicitly wanted this automatic (*"i want automatic this thing happend"*), so `doPost` now calls `ensureStageApprovalTrigger()` on every request, which creates the trigger only if missing (idempotent, checked via `ScriptApp.getProjectTriggers()`). **Bug found and fixed during this change**: the first version called it unconditionally, outside its own try/catch — when the `script.scriptapp` OAuth scope wasn't yet authorized, `ScriptApp.getProjectTriggers()` threw, and since the call sat before the real work in `doPost`, it silently broke *every* Stage 1/Stage 2 submission (not just the trigger), confirmed via live curl tests returning the scope-permission error instead of writing anything. Fixed by wrapping `ensureStageApprovalTrigger()` in its own inner try/catch so a missing-authorization failure there can never block a real submission. The underlying authorization gap itself can't be automated away — Google requires a human to click through a consent screen once per new scope (Mail, in this case); the fix only ensures that gap fails safe instead of breaking the whole endpoint.
- **Scoring moved fully inline into the `.gs` file** (`SCORING_FIELDS` / `SCORING_RULES` / `computeScore()` / `bandFor()`), replacing what used to be a separate Python CLI (`scripts/score_suppliers.py`) that staff ran by hand against a CSV export with its own write-back POST. The user explicitly asked to eliminate that "two files to edit, two deploys to coordinate" friction (2026-07-14: *"add in .gs file so we don't want to save in two time and deploy in two time"*), then explicitly asked to delete `score_suppliers.py` entirely once scoring moved into `.gs` (*"now it's not required .py file so you can remove"*) — **that file is deleted**, along with its write-back call and CLI args. `field_mapping.json`/`scoring_rules.json` are kept only as human-readable reference copies (nothing reads them at runtime now — the `.gs` file's `SCORING_FIELDS`/`SCORING_RULES` constants are the live source of truth). If scoring rules ever change, both the `.gs` constants and the two JSON files need hand-updating to stay in sync (no automated link between them).
- Every submission now writes `Total Score` / `Band` (`Index-leading` ≥85% / `Qualified` ≥65% / `Conditional` ≥40% / `Not currently matched` below, thresholds are a starting default not a locked rule) / `Achievable Max` / `Is Partial` columns automatically — Stage-1-only rows score against a 54-point achievable max (not the full 59), so they don't look artificially low before Stage 2 is done. Verified via a hand-built sample CSV run through the ported logic in Node: Stage-1-only best-tier → 54/54 Index-leading (partial); Stage 2 complete + mass-spec mention → 59/59.
