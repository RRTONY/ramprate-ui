# Seo Content Vs Technical

> SEO audit findings about copy/positioning (titles, meta descriptions, keywords) need explicit approval before editing - technical/schema/accessibility fixes don't

Chitraket reverted a homepage title/meta-description/keywords change I made based on an SEO audit's opinion that "RampRate - Investment & Advisory" was too generic and that mentioning BioChain/peptide sourcing in the homepage description was off-topic dilution. He explicitly said to keep the original wording and not change any keyword - BioChain is a real product line he wants cross-promoted on the homepage, and "Investment & Advisory" is a deliberate positioning choice, not an oversight.

**Why:** SEO audit subagents (seo-content, seo-sxo) score copy/positioning against generic best-practice heuristics ("title should match core service," "don't dilute with unrelated topics"). Those heuristics don't know the business's actual cross-promotion strategy. Several other audit findings from the same session also turned out to be overstated or wrong on direct verification (a claimed regressed internal link that was never regressed, a "thin content" page that was actually a tabs-UI crawlability bug not missing content, a "zero named specialists" claim on a page that already had three real named leaders). Audit output is a lead to verify, not a fact to act on.

**How to apply:** Before editing live title/meta-description/keyword copy based on an SEO audit finding, ask first - these are brand/positioning decisions. Technical fixes (canonical tags, sitemap entries, schema markup, contrast ratios, heading hierarchy, touch-target sizing, dead links, security headers) are fine to fix directly since they're objectively correct/incorrect, not judgment calls. When an audit subagent claims a specific piece of content is missing, broken, or regressed, verify directly (curl the live page, grep the actual component) before trusting the claim - see project_seo_audit_2026-08 for the broader audit-reliability pattern.
