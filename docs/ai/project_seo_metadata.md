# Seo Metadata

> Sanity now drives per-page SEO (title/meta description/keywords/OG image) across all 14 marketing routes

Added a reusable `seo` object schema (`src/sanity/schemas/seo.ts`: metaTitle, metaDescription, keywords, ogImage) and a `pageSeo` document schema (`src/sanity/schemas/pageSeo.ts`) with a `route` dropdown covering all 14 static routes (`/`, `/about`, `/sourcing`, `/growth`, `/web3`, `/impactsoul`, `/private-advisory`, `/process`, `/proof`, `/blog`, `/thinking`, `/contact`, `/careers`, `/expertise`). Each page's `page.tsx`/`layout.tsx` now exports `generateMetadata()` instead of a static `metadata` object: it fetches the matching `pageSeo` doc via `getPageSeo(route)` and overlays any filled Sanity fields onto a `FALLBACK_METADATA` const (same content as before) via `withSeoOverrides()` — both live in `src/lib/sanity/seo.ts`. `page.ts` and `post.ts` schemas were refactored to reuse the shared `seo` type instead of duplicating inline title/description fields.

**Why:** the `page.ts`/`post.ts` schemas previously defined `seo.title`/`seo.description` but the blog/thinking detail pages read `seo.metaTitle`/`seo.metaDescription` — a silent field-name mismatch that meant Sanity-authored SEO overrides for blog/thinking posts never actually applied. Renaming to the shared schema fixed this as a side effect. `siteSettings` also gained a `defaultSeo` field as a site-wide fallback, though nothing consumes it yet.

**How to apply:** All 14 routes' `pageSeo` documents were seeded in Sanity (IDs `pageSeo-home`, `pageSeo-about`, etc.) with the exact text that was previously hardcoded, so editors can now override title/description/keywords/OG image per page from Sanity Studio (`/studio` → Page SEO) without a code change. If a future page is added, add its route to the `ROUTES` list in `pageSeo.ts` and wire `generateMetadata()` the same way. Verified end-to-end by patching a live doc and confirming the rendered `<title>` changed.

See [feedback_avoid_split_deploys](feedback_avoid_split_deploys.md) — this stayed a single Next.js + Sanity artifact, no separate service.
