# Tailwind Over Inline Style

> Chitraket wants inline style={{}} replaced with Tailwind utility classes everywhere, plus a shared/common style system instead of per-page one-off values - reverses the old CLAUDE.md rule

2026-08-10/11: mid-task on an SEO/404 bug fix, Chitraket asked why the codebase uses inline `style={{...}}` for fonts/colors instead of Tailwind classes and asked to convert it everywhere. I flagged that this reversed an explicit, documented CLAUDE.md rule (inline style was previously *mandated* for fonts/oklch colors because they're CSS-variable driven and Tailwind's static class scanner can't see raw `var(--gold)` values). Asked a clarifying question; Chitraket chose "Yes, convert everywhere."

Shortly after, Chitraket separately flagged that pages use "so many different UI and styles" and asked for a **common/shared style and color system** - i.e. not just a mechanical inline-style-to-Tailwind swap, but consolidating repeated one-off patterns (skeleton pulse blocks, badges, opacity values like `rgba(255,255,255,0.06)` re-invented per page) into shared tokens/components.

**What was done this session (first tranche only, not the full site):**
- Registered real Tailwind utility classes in `src/app/globals.css`'s `@theme inline` block, backed by the existing CSS variables: `bg-gold`/`text-gold`/`border-gold`, `bg-dark`/`bg-dark-mid`/`bg-dark-card`, `bg-warm-bg`/`bg-warm-light`, `text-rust`/`border-rust`, `text-ink`/`text-ink-mid` (maps to `--text-dark`/`--text-mid`), `font-display`/`font-body`/`font-mono`. Verified via built CSS output that these compile to real rules (`color-mix()` for opacity modifiers), not silently dropped classes.
- Converted `src/app/not-found.tsx`, `src/app/error.tsx`, and `src/app/blog/page.tsx` (including its `BlogSkeleton`/`EmptyState` subcomponents) off inline style, as a working example of the pattern.
- Updated the CLAUDE.md "Coding Rules" section to reverse the old mandate and describe the new token classes. `global-error.tsx` stays hardcoded inline (documented Next.js exception - renders outside the root layout, `globals.css` never loads there).
- **Not done yet**: the other ~85 `page.tsx` files across the site still use the old inline-style convention. Full conversion + consolidating repeated UI patterns (skeletons, badges, icon cards, eyebrow labels - several already have named templates in CLAUDE.md's "Page Patterns" section) into shared components is a large follow-up, flagged to Chitraket as its own phase rather than done unprompted in one pass given the size and visual-regression risk with no screenshot-diffing available.

**How to apply:** when told to keep working on this, don't restart from scratch - the token infra in `globals.css` already exists, follow the exact pattern in `src/app/blog/page.tsx`/`not-found.tsx` as the reference conversion. When converting a page, check CLAUDE.md's "Page Patterns" section first for whether the piece being touched (icon card, eyebrow label, stat glass-card) already has a documented shared template - use it instead of re-deriving one-off values. Truly per-render-dynamic values (e.g. `animationDelay` computed from a loop index) legitimately stay as inline `style={{}}` - Tailwind can't statically extract those into class names; only migrate the *static* values.
